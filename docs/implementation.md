# Implementation plan and review

## Assumptions

A room has one currency; expenses split equally between explicitly selected participants. Each expense has one payer. The five-digit code is generated by the server; the creator chooses a shared password. Everyone with access can edit. Only the creator's browser retains the separate deletion key. Expiry runs from room creation, not last activity. The app remains local and unpublished.

## Room-flow update

New rooms use an exactly four-digit ASCII PIN, including leading zeroes. Existing room passwords remain valid. Hosts can prepare the people and expenses immediately; guests authenticate then identify themselves using a listed person or a new name. Selecting an existing person preserves their original participant ID and all expense assignments. Identity choice is remembered per tab, and can be changed using the name badge. Names are not exclusive account claims.

Replaced CSV with a locally rendered PNG summary. It includes the room name, currency, total, per-person paid/share/balance, and suggested transfers. Variable canvas height handles the supported group size; long names wrap. No exchange rates or automatic currency conversion are introduced.

Validation: 10 API tests, 4 calculation tests, and a production build pass. Browser checks confirmed a leading-zero PIN, host-created guest selection with existing debts, creation of a new identity, profile restoration on reload, default payer selection, mobile name-picker layout, and a real PNG download inspected visually.

## Receipt, profile and split update

- PIN entry uses four labelled single-digit boxes with numeric keyboard hints, next/previous navigation, and whole-PIN paste. Leading zeroes are preserved. Legacy room passwords remain accessible through the join form’s older-password option.
- Animal avatars use original SVG illustrations for cat, capybara, dog and chameleon. They are stored per person in existing room JSON, so no database schema migration is needed. A profile picker lets the selected person change their animal without changing their expense identity. Existing people have deterministic fallback animals.
- Item allocations store optional fixed integer-cent amounts keyed by participant ID. Selected participants without a fixed amount split the remainder equally. Zero fixed shares are valid. Both UI and API reject negative, fractional-cent, outsider, over-total or incomplete fully fixed allocations. Settlement calculations use the resolved shares exactly.
- Receipt preview is read-only and includes every expense before the per-person and settlement sections. Previewing never downloads automatically. Users can zoom inline or explicitly download PNG pages. The in-app browser disallowed blob navigation in a new tab, so inline zoom replaces that action. Long receipts paginate to avoid browser canvas limits.
- Verification: production TypeScript/Vite build; 9 calculation tests; 12 API tests; browser checks at 1440px and 390px. Confirmed digit focus and whole-PIN paste, guest edits to fixed shares, remainder penny handling, invalid-total feedback, avatar persistence across reloads, mobile custom-share layout, preview image contents, inline zoom and PNG download.

## Optional expense date

Added a date-only input defaulting to the browser’s local calendar day on new expenses, with date display beside the payer and in read-only receipt images. Editing older undated items does not invent a date. Server validation accepts valid dates or null and stamps new expenses with an immutable UTC creation timestamp; existing creation timestamps cannot be changed by a client. Legacy items keep unknown timestamps. Serialization uses JSON mode for date/datetime values.

Validation: production build, 15 frontend tests, and 19 backend tests pass. A temporary-room live Neon verification saved and reloaded the chosen date and server timestamp, confirmed both directly in Postgres, and deleted the verification room. No existing expenses were changed by verification. New date-input layout has not been checked in a live browser in this session.
